# مقایسهٔ IP

## چه چیزی بررسی می‌شود و چرا

ماژول ابتدا درون گروه سرویس‌های روسی و گروه سرویس‌های غیرروسی، اجماع را جداگانه می‌سازد و سپس نشانی‌های عمومی معیار آن‌ها را برای آشکارکردن تفاوت‌های مسیریابی مقایسه می‌کند.

## نتیجه چه معنایی دارد

اختلاف می‌تواند نشان‌دهندهٔ split tunneling، VPN یا proxy، خطای سرویس، خانواده‌های متفاوت نشانی یا وضعیت گذرای شبکه باشد. این نتیجه هیچ علت مشخصی را ثابت نمی‌کند.

## محدودیت‌ها و مثبت‌های کاذب احتمالی

شکست جزئی سرویس‌ها، تفاوت IPv4 و IPv6، captive portal یا transition شبکه می‌تواند اجماع را موقتاً مختل کند. پیش از ایجاد تغییر، آزمون را روی شبکهٔ پایدار تکرار کنید.

## توصیه‌ها برای این بردار

پروژهٔ بیرونی [gowarp-server](https://github.com/paulkarpunin/gowarp-server) پیکربندی WARP روی سرور Linux روت‌شده را شرح می‌دهد. این ادعا تضمین بررسی‌شده در پروژه برای دورزدن مقایسهٔ IP نیست. فرمان curl-to-bash را بدون بازبینی اجرا نکنید. ابتدا script را بررسی کنید، تغییرات firewall و routing آن را راستی‌آزمایی کنید، نسخهٔ پشتیبان بگیرید و روی VPS جداگانه‌ای با مسیر بازیابی شناخته‌شده بیازمایید. سپس هر دو گروه بررسی‌کننده را دوباره اجرا کنید.

## مجوزهای لازم و خطرها

خود بررسی از دسترسی شبکهٔ موجود برنامه استفاده می‌کند. تغییر WARP یا VPS به روت روی سرور نیاز دارد و در صورت پیکربندی اشتباه routing یا firewall می‌تواند اتصال را قطع کند. این روش نشانگرهای بومی محلی، روت دستگاه، firmware سفارشی یا تشخیص سمت سرور را پنهان نمی‌کند.

## سطح شواهد

**بررسی‌شده در پروژه:** منطق اجماع و مقایسه در RKNHardering پیاده‌سازی و آزمایش شده است. **ادعاشده توسط پروژهٔ بیرونی:** آرایش WARP یا VPS همچنان مشروط است.
